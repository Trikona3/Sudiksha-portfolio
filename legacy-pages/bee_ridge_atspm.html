Bee Ridge ATSPM Dashboard

Case Study

Data-heavy dashboard UX

Operational analytics dashboard for traffic signal performance monitoring

Bee Ridge ATSPM is an interactive analytics platform for exploring corridor-level and intersection-level signal performance using maps, filters, KPIs, rankings, heatmaps, clustering, and change detection.

Project Description

The dashboard turns ATSPM measures of effectiveness into a structured decision-support workflow. It helps transportation analysts move from corridor summaries to intersection diagnostics, ranking, day-hour patterns, clustering, and historical change monitoring without starting from raw tables.

UI/UX Design Approach

Dense but readable

The interface prioritizes comparison, filtering, and repeated investigation for analysts, researchers, and traffic engineers.

Map-first context

Interactive maps keep each signal tied to a physical intersection instead of treating data as abstract table rows.

Progressive disclosure

Users start with KPIs and maps, then drill into charts, heatmaps, clusters, change cards, and validation tables.

Design Decisions

Because the project contains dense ATSPM metrics, rankings, clustering outputs, maps, and validation tables, the design avoids decorative UI and uses hierarchy, color, and interaction patterns to make complex traffic data easier to scan.

Color was treated as information, not branding: green points to healthier states and active selections, orange suggests pressure or delay, red flags anomalies or failures, and softer neutrals keep the interface professional instead of loud.

Each tab answers one operational question

The dashboard is organized around questions like what is happening across the corridor, which intersection needs attention, when issues occur, which time slots behave similarly, and what changed compared to history.

Color supports decisions, not decoration

Green, orange, red, muted neutrals, and soft cluster colors communicate performance, caution, alerts, readable intensity, and behavioral groups without making the dashboard feel noisy.

Spatial analysis stays tied to the map

Clickable markers, selected-signal rings, corridor path lines, rank/status colors, and synchronized side lists connect performance metrics back to real corridor locations.

Advanced analytics are translated into readable patterns

DBSCAN and HDBSCAN outputs are shown as labeled day-hour grids, with cluster summaries that explain time bands, day patterns, mean MOE profiles, example slots, and outliers in plain language.

Key Screens

The page moves from corridor overview to ranked diagnostics, then into timing analysis, clustering, and change detection. Each screen is tuned to answer a different question without losing the corridor context.

Overview

A clean corridor summary that uses the map, KPI cards, and muted alerts to set the tone before users drill into details.

Cluster grid

The day-hour clustering view turns DBSCAN output into a readable grid with soft color grouping and outlier labeling.

3D day-hour view

A dimensional view of timing patterns that makes dense MOE behavior easier to compare across weekdays and hours.

Day-hour table

The table keeps the heatmap honest by showing exact values while still using color to surface stronger and weaker cells.

Change detection

The map and side filters isolate the selected intersections, while the layout keeps the attention on change rather than decoration.

Trend charts

Line and bar charts show how wait and termination behavior move over time, with restrained color used to separate the story from the noise.

Composite ranking map

Ranked intersections stay anchored to geography so users can connect the worst-performing locations back to the corridor itself.

Quartile table

The table uses quartile coloring to make comparison faster while still keeping the exact numbers visible for auditability.

Change in average wait

This view compares present values against history so the strongest changes stand out without burying the baseline distribution.

Key Workflows

Dashboard overview

Combines a corridor map, filters, KPI cards, phase summaries, trend charts, signal comparisons, insights, tables, and a metric glossary.

Ranking and prioritization

Uses configurable composite scoring, map markers, ranked lists, scatter/bubble charts, and quartile-colored tables to surface worst-performing intersections.

Day-hour analysis

Heatmaps and 3D surface plots help users identify when traffic issues happen across weekdays, hours, phases, and selected MOEs.

Clustering and change detection

DBSCAN, HDBSCAN, and historical comparison views translate advanced analytics into cluster grids, summaries, outlier counts, and flagged change cards.

Visual Encoding

Color as information

Green signals healthier or active states, orange and red highlight pressure or change, and heat intensity helps users scan high MOE values quickly.

Ranking design

Color-coded rank markers and quartile table cells help users identify stronger and weaker intersections without comparing every number row by row.

Heatmaps for recurring timing patterns

Day-hour heatmaps answer when issues happen, making weekday peaks, afternoon delay spikes, and high-value MOE cells visible before users open raw detail.

Tables for auditability

Compact tables preserve the exact values behind each insight, with clear labels and metric-specific coloring so precision stays available after the charts summarize the story.

Outcome

Bee Ridge ATSPM evolved from a traffic visualization tool into a full analytics system for corridor monitoring, signal diagnosis, ranking, pattern discovery, bottleneck clustering, and historical change detection.
